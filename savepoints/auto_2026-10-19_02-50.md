## The ₱ bug: root-caused, fixed, verified on-device

**Cause:** `CurrencyPreferences.saveToStorage()` wrote `userPrimaryCurrency` unconditionally.
At first launch `CashMonkiApp` calls `setSecondaryCurrency(.usd)` (secondary is nil), which
called `saveToStorage()` and persisted the `.php` *default* as if the user had chosen it. The
startup guard `if string(forKey:"userPrimaryCurrency") == nil` then never fired again — log said
"preserving user's choice" for a choice never made. US users got ₱ with amounts converted
**into** pesos (`Converting 22.0 USD → PHP`).

**Fix** (`CurrencyPreferences.swift`):
- `deviceDefaultCurrency` from `Locale.current.currency` replaces hardcoded `.php`
- `saveToStorage()` writes the primary key only when `hasSetPrimaryCurrency` is true
- `setPrimaryCurrency()` sets that flag (explicit call = real choice)
- `resetToDefault()` returns to the device guess

**Verified** on sim 372F7589 (region forced en_US), after `simctl spawn defaults delete` +
sim reboot to clear cfprefsd:
```
No stored primary currency, using default: USD
Initialized with primary: USD, secondary: none
ContentView: ... USD ($ - USD)
```
plist after launch: `userPrimaryCurrency` **absent**, `hasSetPrimaryCurrency` absent. Before the
fix the same path produced PHP/₱.
