### Duplicate subscription transaction — root-caused + fixed
Symptom: "Supabase" ₱2,054.26 / $35 Aug 1 9pm appeared TWICE after a cloud load. Cause: `SubscriptionManager.processSubscriptions` (~:383) loops `while subscription.isDue` with **no existence check**, so each device mints its own UUID for the same due date; `mergeTransactions` is union-by-id so both survive; `RecurringTransactionManager.transactionExistsForDate` only sees the local array. Fix = `collapseGeneratedDuplicates` (UserManager ~:1943), run at end of every merge. Occurrence key = (`subscriptionId ?? recurringTemplateId`, due minute, amount) — date comes from `nextDueDate`, identical across devices. Winner deterministic (newer `syncMetadata.lastModified`, tie → smaller uuid string) so devices converge; loser tombstoned via `tombstoneTransaction`. Existing dupes collapse on next merge; log line `🧹 UserManager: collapsed duplicate occurrence`. **Not yet verified at runtime by the user.**
Known assumption: two same-minute same-amount charges from one subscription are treated as impossible.
