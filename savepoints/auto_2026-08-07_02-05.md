## What was built this session (Ask tab AI + one wallet bug)

### 1. Multi-transaction add
New `transaction_draft_batch` message type (2-10 rows). One card, per-row `+`, tap a row to edit it
in the full AddTransactionSheet, `Add all N` button. Added rows dim and show ✅; card retires only
when every row is in.
- `Models/AskMessageSchema.swift` — `AskTransactionDraftBatch`; decoder case collapses a 1-row batch
  to a plain `transaction_draft`.
- `Pages/AskPage.swift` — `AskDraftBatchCard`, `addBatchRows`, `markBatchRowAdded`,
  `addedBatchRows: [UUID: Set<Int>]` (persisted).

### 2. Budgets: add / edit / delete via AI (user chose full CRUD)
`budget_draft`, `budget_update`, `budget_delete` — all Confirm-gated, model never writes.
- `Functions/AskChatService.swift` — `createBudget` / `updateBudget` / `deleteBudget` /
  `resolveBudgetCategory` (subcategory id folds up to its parent; budgets are parent-scoped),
  `BudgetWriteError`.
- `get_budgets` rows now carry `id`, `category_id`, `currency`, `active`, and **no longer filter to
  isActive** — otherwise the AI could pause a budget and never see it again to resume.
- `Pages/AskPage.swift` — `AskBudgetDraftCard` / `AskBudgetUpdateCard` / `AskBudgetDeleteCard` over a
  shared `AskBudgetCardShell`. Positive action only (Yes/Confirm/Delete), matching the category card.
- Prompt steers pause (`is_active: false`) ahead of delete.

### 3. Pending cards are chat-revisable (the actual user complaint)
A pending draft's history line only said "100 PHP … awaiting Confirm", so "make it 150" had nothing
to work from — the model could only see ALREADY-ADDED transactions.
- `historyText` now reports every pending card's FULL values, marked "PENDING, not saved yet".
- `Content.isPending`; new `appendPending()` supersedes older pending cards → they render as
  "Replaced by the updated suggestion below" (`supersededCards: Set<UUID>`, persisted). Prevents
  tapping two cards and writing twice. A partly-added batch keeps its remaining rows live.
- systemPrompt: new CRITICAL block — revise a pending card by emitting a fresh FULL card of the same
  type; never claim an update in text alone. Plus: never show raw ids as a table column.
- `PersistedChat` gained optional `superseded` + `batchRows` (optional = old files still decode).

### 4. Selected wallet now persists (`Managers/AccountManager.swift`)
Root cause of "every app update it keeps changing": `setupDefaultAccount()` unconditionally did
`selectedSubAccountId = defaultAccountId` on EVERY `UserManagerFirebaseLoadComplete`, and the
selection was never stored. Now `selectedSubAccountId` has a `didSet` writing
`selected_wallet_id_<uid>` to UserDefaults (uid resolved exactly like the chat's `currentUID()`), and
setup restores it when that wallet still exists, else falls back to the default.
