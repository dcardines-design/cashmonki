## Key architecture decision (from 3-agent review)
There were TWO competing sync engines. `TransactionSyncManager` (System B) keyed Firestore by `currentUser.id.uuidString` (app UUID, not firebaseUID), ignored tombstones (resurrected deletes), replaced-not-merged (clobbered), ignored `enableFirebaseSync`. Killed it; `UserManager` (System A: delta `pushTransactionToCloud` + merge-on-load) is now the SOLE engine.

## 5 phases done (all built)
1. **Killed TransactionSyncManager** — `startSync()` neutered (early return); `UserManager.forceSync`/status proxies repointed to System A flags (`isSyncingToCloud`/`lastCloudSyncAt`/`lastCloudSyncFailed`). `SyncStatus` enum cases carry associated values (`.synced(lastSyncDate:)`, `.error(message:)`).
2. **Canonical `syncUID()`** on UserManager = `firebaseUID ?? last_authenticated_firebase_uid ?? currentUser.id.uuidString`. Replaced 13 churning `?? currentUser.id.uuidString` key fallbacks. `stableDefaultWalletID()` now uses it.
3. **Write amplification** — FLIPPED default: `syncToFirebase` = user-doc-only (merge:true, no txn loop); new `fullSyncToFirebase` = doc + all txns, used only by bulk-txn callers (finishClaim, forceSync, uploadSampleData, forceManualSync, migration ~2736). `saveUserData` strips `transactions` key + `setData(merge:true)`.
4. **Sync parity** — subscriptions → cloud (`users/<uid>/subscriptions/all`, SubscriptionManager push on save + merge on reload); added 7 dropped fields to UserData Codable (`role, moneyStress, overspentRealization, trackingDifficulty, idealOutcome, trackingFrequency, trackingMethod`); budgets update/delete now reach cloud via light path.
5. **Hardening** — tombstones now PER-USER (`deletedTransactionIDs_<syncUID>`, legacy global migrates in, capped 2000). Skipped accountID/walletID rename (too risky).
