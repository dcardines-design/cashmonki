# Savepoint — 2026-07-08 23:07

## Task
Activate cloud sync (Firebase/Firestore) **default ON** for CashMonki, so user data survives app deletion / reinstall. Auth itself already fully built (Firebase email/pw + Google + Apple) — real work was data durability, not login.

## Key context / findings
- Data persisted **locally** in UserDefaults, key `currentUser_firebase_<firebaseUID>` (`UserManager.swift:~2125`).
- iOS wipes UserDefaults on app delete → **delete app = data gone** unless synced.
- Firestore sync machinery **already fully built** (`FirestoreService`, `syncToFirebase()`, `loadFromFirebase()` which merges accounts + loads tx). Just gated off.
- `enableFirebaseSync` defaulted `false` at 3 sites; `restoreUserSession()` never touched cloud.
- Struct default already `true` (`Models.swift:1453`); Google/Apple paths already `true`.

## Decision: SAFE conflict rule
**Cloud restores ONLY when local is empty; otherwise local wins + uploads.** Never overwrite good local with empty/stale cloud. (User stressed "data is precious.")

## Changes made (all `Functions/UserManager.swift`)
1. 3 defaults flipped `false`→`true` (lines ~60, ~260, ~315).
2. New helper `migrateEnableSyncIfNeeded()` — for existing users w/ stored `false`: enable sync + push local→cloud (upload only, never pull). Wired into both "local data found" paths (`restoreUserSession` Step 1 + `setCurrentUser` local branch).
3. `restoreUserSession()` Step 2 restructured: when local empty + authenticated → `loadFromFirebase()` to restore (reinstall/new device), then save local. Dev/test (no auth) → empty, unchanged. Added early `return`s.

## Known limitations / open decisions
1. **Can't recover already-lost data** (users who deleted before this had nothing in cloud). Forward-fix only.
2. **Opt-out consent gap**: sync-off pref keyed by unstable per-session UUID (`enableFirebaseSync_<id>`) → a user who turned sync OFF may get re-enabled+re-uploaded next launch. Data-safe but privacy issue. Offered to re-key by email/firebaseUID — awaiting user.
3. **Multi-device**: no live merge; only reinstall-restore covered.
4. Cosmetic: cloud restore may leave 1 extra empty default wallet (mergeAccounts).
